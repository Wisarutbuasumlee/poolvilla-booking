## D-001 ราคาเป็นสองชั้น บริษัทตั้งฐาน นายหน้าบวกเพิ่ม

**วันที่** 2026-09-08 · **ผู้ตัดสิน** เจ้าของโปรเจกต์

สเปกเดิมเขียนว่าราคาอยู่ที่ `villa_agents` อย่างเดียว และบ้านไม่มีราคา แต่ธุรกิจจริงทำงานอีกแบบ บริษัทมีราคาเดิมของบ้านอยู่แล้ว แล้วแบ่งบ้านให้นายหน้าในเครือไปบวกราคาเพิ่มเอง

จึงเก็บเป็น `villas.basePricing` กับ `villas.baseOverrides` สำหรับราคาบริษัท และ `villa_agents.markup` กับ `villa_agents.markupOverrides` สำหรับยอดบวกเพิ่มของนายหน้า ราคาคืนหนึ่งคือ ราคาฐานที่ resolve แล้ว บวก ยอดบวกเพิ่มของประเภทวันเดิมของคืนนั้น

**ทำไม** ถ้าเก็บเป็นราคาเต็มของนายหน้า พอบริษัทขึ้นราคาฐานต้องไล่แก้ทีละคน และจะมีนายหน้าที่ลืมแก้ขายต่ำกว่าทุน

**ผลข้างเคียงที่ได้เปล่า** หน้าค้นหาตอนไม่มีนายหน้าไม่ต้อง query `villa_agents` เลย เพราะราคาฐานอยู่ในเอกสารบ้านที่โหลดมาแล้ว

**ที่ยังค้าง** เมื่อรายได้ของนายหน้าคือส่วนบวกเพิ่ม แล้ว `commissionRate` ใช้ทำอะไร ตอนนี้เก็บทั้งสองฟิลด์ ตั้งค่าคอมเริ่มต้นเป็นศูนย์ คิดจากราคาฐาน รอยืนยันตอน Phase 5

## D-002 วันที่เก็บเป็นสตริง ไม่ใช่ Date

**วันที่** 2026-09-08

ทุกวันที่ที่มีความหมายเชิงปฏิทินเก็บเป็น `DateKey` คือสตริง `'YYYY-MM-DD'` ตามเวลาไทย ทั้งใน MongoDB และในหน่วยความจำ หาวันในสัปดาห์ด้วย `new Date(key + 'T00:00:00Z').getUTCDay()` ซึ่งให้ผลถูกต้องไม่ว่า host จะตั้ง timezone อะไร

**ทำไม** MongoDB เก็บ `Date` เป็น UTC เครื่องพัฒนาตั้งเป็นเวลาไทย เซิร์ฟเวอร์จริงตั้งเป็น UTC ถ้าเก็บเป็น `Date` แล้วอ่านกลับด้วย accessor แบบ local จะได้คนละวัน อาการที่ออกมาคือ "ราคาผิดเฉพาะการจองหลังห้าโมงเย็น" ซึ่งเป็นบั๊กที่ทำซ้ำยากที่สุดประเภทหนึ่ง

การเรียงตัวอักษรของรูปแบบนี้ตรงกับการเรียงตามเวลา index จึงใช้ได้ปกติ

**บังคับด้วย** ESLint `no-restricted-syntax` ห้าม `getDay` `getMonth` `getDate` นอก `src/lib/pricing/dates.ts`

## D-003 กันจองชนด้วย unique index ไม่ใช่ transaction

**วันที่** 2026-09-08

`availability` มี unique compound index บน `{villaId, dateKey}` การจองค้างยิง `bulkWrite` แบบ `ordered: false` เป็น conditional upsert ทีเดียวทุกคืน คืนที่คนอื่นถืออยู่จะชน `E11000` ทำให้รู้ทุกคืนที่ชนในรอบเดียว ถ้าได้ไม่ครบก็ลบเฉพาะของตัวเองด้วย `deleteMany({villaId, bookingId})` ซึ่งแตะของคนอื่นไม่ได้

**ทำไม** MongoDB ตัวเดียวที่ไม่ได้ตั้ง replica set ทำ transaction ไม่ได้เลย `startTransaction` จะล้มด้วย `IllegalOperation` ถ้าออกแบบให้พึ่ง transaction ระบบจะพังตั้งแต่ `npm run seed` ครั้งแรกบนเครื่องนักพัฒนา และสิ่งที่จะเกิดขึ้นจริงคือมีคนถอด transaction ออก "ชั่วคราว" แล้วไม่ใส่กลับ

ถึงอย่างนั้นยังรัน Mongo เป็น single-node replica set และห่อด้วย `withTxn()` ที่เปิดปิดด้วย env `MONGODB_TRANSACTIONS` เพื่อให้ transaction เป็นชั้นเสริม ไม่ใช่ชั้นที่ขาดไม่ได้

**ห้าม** ใส่ TTL index บน `holdExpiresAt` มันดูเหมือนจะทำงานได้เพราะการไม่มีเอกสารแปลว่าว่าง แต่ TTL วิ่งเป็นรอบพื้นหลังที่ปรับไม่ได้ และถ้ามีเอกสาร `blocked` ติด `holdExpiresAt` มาโดยบังเอิญ TTL จะลบวันที่แอดมินบล็อกไว้เงียบ ๆ

## D-004 ไม่ใช้ auth บน MongoDB ในเครื่องพัฒนา

**วันที่** 2026-09-08

`docker-compose.yml` รัน mongo แบบ replica set โดยไม่เปิด `--auth` และเปิดพอร์ตเฉพาะ `127.0.0.1`

**ทำไม** การเปิด `--auth` พร้อม `--replSet` ต้องมี keyFile ที่สิทธิ์ต้องเป็น `0400` ไฟล์บน bind mount ของ Windows ออกมาเป็น world-readable เสมอ mongod จึงไม่ยอมสตาร์ตด้วยข้อความ `permissions on keyfile are too open` ทางแก้อีกทางคือใช้ named volume กับ init container ซึ่งซับซ้อนกว่าประโยชน์ที่ได้ในเครื่องพัฒนา

`docker-compose.prod.yml` เปิด auth เต็ม

## D-005 ใช้ Next.js 16 ไม่ใช่ 15

**วันที่** 2026-09-08

สเปกเขียนว่า "Next.js 15+" ตอนเริ่มโปรเจกต์ 16.3.4 เป็นตัวล่าสุด ส่วน 15.x อยู่ใน dist-tag `backport` แล้ว ตรวจแล้วว่า `next-intl` และ `next-auth` ประกาศ peer รองรับ `^16.0.0` ทั้งคู่

**ผลที่ตามมาที่ใหญ่ที่สุด** Next 16 เปลี่ยน `middleware` เป็น `proxy` และ proxy รันบน **Node runtime** ไม่ใช่ Edge ซึ่งลบปัญหาการแยก edge กับ node ของ Auth.js ทิ้งไปทั้งก้อน ไฟล์คือ `src/proxy.ts` และฟังก์ชันชื่อ `proxy`

**ผลอื่น** `revalidateTag` ต้องมีอาร์กิวเมนต์ที่สองเป็น cacheLife profile, `next lint` ถูกถอดออกให้เรียก eslint ตรง ๆ, `images.qualities` เริ่มต้นเหลือ `[75]`, parallel route ต้องมี `default.js`

## D-006 ยังไม่เปิด cacheComponents

**วันที่** 2026-09-08

หน้ารายละเอียดบ้านจะใช้ `unstable_cache` กับ tag ไปก่อน ไม่เปิด `cacheComponents` ใน Phase 0

**ทำไม** การเปิด cacheComponents ไม่ใช่การเปลี่ยนชื่อ flag มันทำให้ข้อมูลที่ไม่ได้แคชและอยู่นอก `<Suspense>` กลายเป็น build error ซึ่งเป็นการเปลี่ยนโมเดลทั้งแอป โครงที่วางไว้เข้ากันได้อยู่แล้วเพราะราคาที่ขึ้นกับ cookie ถูกแยกไว้ใน Suspense boundary ของตัวเอง จึงกลับมาพิจารณาอีกครั้งตอน Phase 3

## D-007 ESLint 9 ไม่ใช่ 10

**วันที่** 2026-09-08

`typescript-eslint@8.70.0` ประกาศ peer ว่ารองรับ `eslint@^10` แต่ใช้จริงแล้วพังด้วย `TypeError: scopeManager.addGlobals is not a function` เพราะ scope manager ที่มันสร้างยังเป็นของ eslint-scope รุ่นเก่า ล็อก ESLint ไว้ที่ 9.39.5 จนกว่า typescript-eslint จะออกตัวที่แก้แล้ว

ด้วยเหตุผลเดียวกัน TypeScript ล็อกที่ 5.9.3 เพราะ typescript-eslint ประกาศ peer ว่า `>=4.8.4 <6.1.0` ยังไม่รองรับ TypeScript 7

## D-008 ไม่ใช้ type-aware linting

**วันที่** 2026-09-08

ถอดกฎ `consistent-type-imports` ออก

**ทำไม** มันต้องการ type information ซึ่งแปลว่าต้องรัน TypeScript program ทุกครั้งที่ lint และต้องตั้ง parser ทับตัวที่ `eslint-config-next` ติดตั้งมา ราคาแพงกว่าประโยชน์ กฎที่กันบั๊กจริงคือ `no-restricted-imports` และ `no-restricted-syntax` ซึ่งทำงานได้โดยไม่ต้องมี type

## D-011 ภาษาจีนไม่โหลดเว็บฟอนต์

**วันที่** 2026-09-08

**ทำไม** ฟอนต์ CJK ตัวหนึ่งใหญ่หลายเมกะไบต์ และทุกเครื่องที่อ่านภาษาจีนได้มีฟอนต์จีนที่ดีอยู่แล้ว การโหลดเพิ่มเสียมากกว่าได้
