# Handover

สิ่งที่มีอยู่ สิ่งที่ยังต้องทำก่อนเปิดใช้จริง และเรื่องที่ห้ามลืม

## สถานะ

ทั้งเก้า Phase ตามสเปกทำครบแล้ว ระบบรันได้ครบวงจรตั้งแต่ลูกค้าค้นหาบ้าน จองและแนบสลิป ไปจนถึงเจ้าหน้าที่ยืนยันและดูรายงาน

| ส่วน | สถานะ |
|---|---|
| หน้าบ้าน หน้าแรก ค้นหา รายละเอียดบ้าน | ใช้งานได้ |
| ระบบจอง กันวัน 30 นาที ชำระเงิน แนบสลิป ตรวจสอบการจอง | ใช้งานได้ |
| หลังบ้าน จัดการบ้าน รูปภาพ การจอง ปฏิทินรวม | ใช้งานได้ |
| ระบบนายหน้า ลิงก์อ้างอิง พอร์ทัล ราคาบวกเพิ่ม | ใช้งานได้ |
| แดชบอร์ด รายงาน export CSV | ใช้งานได้ |
| สามภาษา ธีมสว่างและมืด SEO | ใช้งานได้ |
| Docker ทั้งสแตก | ใช้งานได้ ทดสอบยกจริงแล้ว |

## ต้องทำก่อนเปิดให้ลูกค้าจริง

เรียงตามความสำคัญ ข้อบนสุดคือของที่ขาดแล้วเปิดไม่ได้

1. **รูปถ่ายจริง** ตอนนี้ทุกรูปเป็นแผ่นสีที่มีรหัสบ้านพิมพ์อยู่ ติดธง `isSynthetic` ไว้ทุกใบ และหน้าเว็บติดป้ายว่า "รูปตัวอย่าง" ให้เห็น อัปโหลดรูปจริงผ่านหน้าจัดการบ้านแล้วลบรูปตัวอย่างทิ้ง
2. **ข้อมูลบ้านจริง** บ้านสิบหลังในระบบเป็นข้อมูลตัวอย่าง มีแค่ DV-2685 ที่ถอดมาจากสเปกจริง
3. **วันหยุดตามจันทรคติ** มาฆบูชา วิสาขบูชา อาสาฬหบูชา และวันเข้าพรรษา ต้องกรอกเองทุกปี ระบบไม่เดาให้เพราะเดาผิดแล้วจะคิดราคาวันหยุดกับการจองจริงโดยไม่มีใครรู้
4. **บัญชีธนาคารและพร้อมเพย์จริง** ตั้งในหน้าตั้งค่า ตอนนี้เป็นเลขตัวอย่าง
5. **โดเมนจริงและใบรับรอง TLS** ต้องมีสองชื่อ คือโดเมนหลักกับ `admin.` ชี้มาที่เครื่องเดียวกัน
6. **เปลี่ยนรหัสผ่านแอดมิน** รหัสที่ seed สร้างเป็นรหัสสำหรับพัฒนาเท่านั้น
7. **ตั้ง cron เรียกตัวกวาดล้าง** ทุกห้านาที ดู `DEPLOYMENT.md`

## เรื่องที่ยังค้างในการออกแบบ

**ค่าคอมมิชชั่นกับส่วนบวกเพิ่ม** ตอนนี้รายได้ของนายหน้าคือส่วนที่บวกเพิ่มเอง และ `commissionRate` ตั้งไว้ที่ศูนย์ ถ้าบริษัทจะจ่ายค่าคอมเพิ่มจากราคาฐานด้วย ให้ตั้งค่าในหน้าจัดการนายหน้า ระบบคำนวณและบันทึกไว้ในทุกการจองอยู่แล้ว

**ยอดบวกเพิ่มตามช่วงเทศกาลของนายหน้า** โครงสร้างข้อมูลรองรับแล้ว (`markupOverrides`) แต่ยังไม่มีหน้าจอให้นายหน้าตั้งเอง ตอนนี้ตั้งได้เฉพาะราคาสี่ประเภทวัน

**iCal sync กับ Airbnb และ Booking.com** ยังไม่ได้ทำ ปฏิทินพร้อมรองรับแล้วเพราะเก็บเป็นวันต่อวัน

## สิ่งที่ตัดสินใจไว้แล้วและห้ามเปลี่ยนโดยไม่อ่านเหตุผลก่อน

รายละเอียดเต็มอยู่ใน `docs/DECISIONS.md` สรุปที่สำคัญที่สุดสามข้อ

**กลไกกันจองซ้อนคือ unique index ไม่ใช่ transaction** ถ้ามีใครถอด index `uniq_villa_date` ออก ระบบจะจองซ้อนได้ทันทีโดยไม่มีอะไรเตือน เทสต์ยิงพร้อมกัน 20 เส้นมีไว้เฝ้าเรื่องนี้

**วันที่เก็บเป็นสตริง ไม่ใช่ Date** ถ้าเปลี่ยนกลับ จะเกิดบั๊กแบบ "ราคาผิดเฉพาะการจองหลังห้าโมงเย็น" ที่หาสาเหตุยากมาก เมทริกซ์เทสต์สาม timezone มีไว้เฝ้าเรื่องนี้

**ราคาเป็นสองชั้น** บริษัทตั้งราคาฐานที่บ้าน นายหน้าเก็บเป็นยอดบวกเพิ่ม ไม่ใช่ราคาเต็ม ถ้าเปลี่ยนไปเก็บราคาเต็ม การขึ้นราคาฐานจะไม่ถึงนายหน้า และจะมีคนขายต่ำกว่าทุนโดยไม่รู้ตัว

## การทดสอบ

```bash
npm test                    # 285 เทสต์ เอนจินราคาสามรอบสาม timezone
npm run db:up && npm test   # เพิ่มอีก 18 เทสต์กันจองซ้อนกับฐานข้อมูลจริง
npm run test:e2e            # เดินเส้นทางจริงในเบราว์เซอร์ ต้องมี db:up และ seed ก่อน
```

เทสต์ที่ต้องใช้ MongoDB จะข้ามพร้อมข้อความบอกเมื่อ container ไม่ได้รัน และจะล้มถ้าตั้ง `REQUIRE_DB=true` ซึ่งใช้ใน CI

## บัญชีสำหรับทดสอบ

หลังรัน `npm run seed`

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| แอดมิน | admin@poolvilla.local | poolvilla-dev-2026 |
| นายหน้า 123 | agent123@poolvilla.local | poolvilla-agent-2026 |

ทั้งสองเป็นรหัสสำหรับพัฒนาเท่านั้น เปลี่ยนก่อนขึ้นเครื่องจริง
